Before you begin — the 4 golden rules

Read these once. They prevent 90% of go-live problems.

#RuleWhy it matters
1Run php artisan key:generate only once. Never change APP_KEY after that.If it changes, all saved integration passwords become unreadable and WhatsApp/email stop working.
2The website must serve the public folder, not the project root.Otherwise you get a blank page or a directory listing.
3The Meta "Verify Token" must be identical to the one you type in the CRM.The webhook won't connect if they differ by even one character.
4Write down every value you create as you go.You'll reuse DB credentials, Meta IDs/tokens and the Gmail app password across steps.
About the screenshots: pictures in this guide show the Agrocorp CRM screens you'll use. Steps that happen on another company's website (Hostinger, Meta/Facebook, Google) are written out click-by-click because those screens live on their sites, not inside the CRM.

What you need ready

  1. A Hostinger plan with SSH access (VPS is best; Cloud/Business also work).
  2. Your domain connected to Hostinger.
  3. A terminal on your computer (Windows: PowerShell; Mac: Terminal).
  4. A Facebook login and a Meta Business account (you can create the Business account during Part E).
  5. A Gmail / Google Workspace mailbox you control (e.g. crm@yourdomain.com).
  6. Your own phone (with WhatsApp) and email — you'll use these as the "demo customer" so real messages arrive on screen.
  7. About 2–3 hours. Start early — Meta can take a while to approve message templates.

PART A — Put the code on Hostinger

Get the application files onto your server and point the website at them.

A1. Turn on SSH and connect On Hostinger
  1. Log into Hostinger and open hPanel.
  2. Left menu → Advanced → SSH Access. If disabled, click Enable.
  3. Write down the SSH IP/Host, Port (often 65002) and Username.
  4. On your computer's terminal type, then press Enter:
    ssh -p <Port> <Username>@<Host>
  5. First time it asks to continue → type yes → Enter. Then type your Hostinger password (the characters stay hidden — that's normal).
  6. Go to your domain folder: cd ~/domains/<yourdomain.com> (run ls ~/domains if unsure of the exact name).
A2. Copy the project into a folder named app

Easiest (GitHub):

  1. In the Emergent chat, click Save to GitHub and copy the repository URL.
  2. On the server run: git clone <your-repo-url> app
  3. Wait for "done." — you now have ~/domains/<yourdomain.com>/app.

Alternative (ZIP upload): hPanel → File Manager → open your domain folder → create a folder app → Upload the ZIP → right-click → Extract. Confirm artisan, composer.json, public and routes sit directly inside app.

A3. Make the website show the public folder On Hostinger
  1. hPanel → Websites → click your domain → Dashboard.
  2. Find Website root / Document root (may be under Advanced / Website settings).
  3. Set it to: domains/<yourdomain.com>/app/public and Save.
If your plan has no document-root setting (some serve only from public_html): ask Hostinger support to set the web root, or move the project outside public_html and copy the contents of app/public into public_html, editing the two require paths in public_html/index.php to point to ../app/vendor/autoload.php and ../app/bootstrap/app.php.

PART B — Install & configure the app

Run every command from inside the project folder: cd ~/domains/<yourdomain.com>/app

B1. Install and prepare
  1. Install libraries: composer install --no-dev --optimize-autoloader
  2. Create the settings file: cp .env.example .env
  3. Generate the key once: php artisan key:generate (you'll see "Application key set successfully").
B2. Create the database On Hostinger
  1. hPanel → Databases → MySQL.
  2. Create a database (e.g. agrocorp_crm), a user (e.g. agrocorp_user) and a strong password.
  3. Write down the full names it shows (Hostinger adds a prefix like u123_agrocorp_crm).
B3. Fill in the .env file

Edit .env (nano .env on the server, or File Manager → Edit). Set at least:

APP_NAME="Agrocorp CRM"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://<yourdomain.com>
APP_TIMEZONE=Asia/Kolkata
DB_CONNECTION=mysql
DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=<full db name>
DB_USERNAME=<full db user>
DB_PASSWORD=<db password>
SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true
MAIL_MAILER=log
Leave the APP_KEY line exactly as key:generate created it. Keep MAIL_MAILER=log for now — you'll switch email on from inside the CRM in Part F.
B4. Build the database & finish setup
  1. Create tables: php artisan migrate --force
  2. Load starter data + demo users: php artisan db:seed --force
  3. Make uploads public: php artisan storage:link
  4. Fix permissions: chmod -R 775 storage bootstrap/cache
  5. Speed it up: php artisan config:cache then php artisan route:cache
After any future change to .env, run php artisan config:clear then php artisan config:cache.

PART C — Turn on HTTPS and the scheduler

C1. HTTPS (SSL) On Hostinger
  1. hPanel → Security → SSL → select your domain → Install SSL (free) → wait until "Active".
  2. Turn on Force HTTPS so http:// automatically redirects to https://.
C2. Cron / scheduler — REQUIRED for reminders & campaigns On Hostinger
  1. hPanel → Advanced → Cron Jobs → Create.
  2. Frequency: Every Minute (or set all five boxes to *).
  3. Command (replace the path; run which php to find your PHP path):
    cd /home/<user>/domains/<yourdomain.com>/app && php artisan schedule:run >> /dev/null 2>&1
  4. Save.
Why this matters: without cron, payment reminders, visit reminders and scheduled WhatsApp/email campaigns will never fire.

PART D — First login & a quick health check

  1. Open https://<yourdomain.com> in Chrome or Edge.
  2. Sign in with the seeded admin account (email and password are in your credentials file).
  3. Immediately change the password: top-right avatar → Account Settings → Security.
Blank page or error? On the server run php artisan config:clear, then read the last lines of storage/logs/laravel.log. Usual causes: website root not pointed at /public (A3), wrong DB details (B3), or unwritable storage (rerun the chmod in B4).

PART E — Connect real WhatsApp (fast demo path)

You do not need Business Verification for the demo. Meta gives you a free test number that can message up to 5 phone numbers you verify. Use that.

E1. Create the Meta app On developers.facebook.com
  1. Go to developers.facebook.com and log in with Facebook.
  2. Top-right → My Apps → Create App.
  3. "What do you want your app to do?" → choose Other → Next.
  4. App type → Business → Next.
  5. Name it Agrocorp CRM → pick your Business account if asked → Create app.
E2. Add WhatsApp & copy the credentials
  1. In the app, find the WhatsApp product → click Set up.
  2. You land on WhatsApp → API Setup. Copy and write down: the Temporary access token, the Phone number ID, and the WhatsApp Business Account ID (WABA ID).
  3. Left menu → App settings → Basic → reveal and copy the App Secret.
  4. Invent a Verify Token word, e.g. agrocorp_verify_2026. Write it down.
E3. Add YOUR phone as a recipient
  1. On the API Setup screen, open the "To" dropdown → Manage phone number list.
  2. Enter your WhatsApp number in full international format (e.g. +91XXXXXXXXXX).
  3. Enter the confirmation code Meta sends you on WhatsApp. Repeat for teammates (max 5).
E4. Enter the credentials in the CRM
  1. CRM → Integrations → open Meta WhatsApp Cloud.
  2. Fill: Access Token, Phone Number ID, WABA ID, App Secret, and Verify Token (= agrocorp_verify_2026).
  3. Click Save, then Run connection check — you want "WhatsApp number verified" to be green.
  4. Toggle the integration ON / Enable. Templates auto-sync.
E5. Set the webhook On developers.facebook.com
  1. Meta app → WhatsApp → Configuration → Webhook → Edit.
  2. Callback URL: https://<yourdomain.com>/api/v1/webhooks/whatsapp
  3. Verify token: agrocorp_verify_2026 (exactly as in the CRM) → Verify and save.
  4. Under Webhook fields → Manage → Subscribe to messages.
E6. Create & approve templates
  1. CRM → WhatsApp Templates → New template → fill name (lowercase_with_underscores), body and buttons → Save draft → Submit.
  2. Wait for the status to change to APPROVED (click Sync from Meta to refresh). Submit any templates you'll demo today.
  3. Tip: quick-reply buttons can launch a chatbot — pick a bot in the button's "Launch bot" dropdown.

PART F — Connect real email (Gmail)

F1. Prepare the mailbox On myaccount.google.com
  1. Go to myaccount.google.com → Security.
  2. Turn on 2-Step Verification.
  3. Open App passwords → App: Mail → Device: "Other" → type "Agrocorp CRM" → Generate. Copy the 16-character password.
F2. Enter it in the CRM
  1. CRM → Integrations → Google / SMTP Email.
  2. Host smtp.gmail.com, Port 587, Mailbox (your address), App Password (the 16 characters), From Name/Email.
  3. Click Save → Test (want "SMTP authenticated") → Enable.
  4. Real test: use "Forgot password" or add a lead with your email and check your inbox (and spam).

PART G — Create your demo people

  1. CRM → Users & Roles → add a BDE and a Sales Head with real emails you can open.
  2. Set memorable demo passwords and write them down.
  3. Create the demo customer lead using your own phone + email so every WhatsApp/email lands on your devices on screen.

PART H — The night before

  1. WhatsApp office hours: CRM → Inbound Rules → set business hours to cover the demo time, or turn office hours off. (Outside hours, bots reply with an "away" message.)
  2. Pre-warm the AI dashboard: log in as a Sales user and open the Dashboard once (the first load is slow ~10–30s, then instant).
  3. Templates: confirm the ones you'll show say APPROVED.
  4. Full dry-run: do the whole demo once, end to end, with your phone + email as the customer.
  5. Backup: screen-record the dry-run in case the internet misbehaves.

PART I — Run the demo (matches your 12 points)

A smooth order that tells a story from first contact to a paying customer.

1–2. Admin login & team

Log in as admin and show the company-wide dashboard, then open Users & Roles to show the team by department.

3–4. Project & inventory mapping
5–6. Integrations & templates

Open Integrations and show WhatsApp + Email connected (green), then show an APPROVED WhatsApp template. Optionally show the WhatsApp Bots builder.

7–8. Lead capture & round-robin

Capture a lead from a source (website form / chatbot, or message your WhatsApp test number from your phone), and add one manually to show round-robin auto-assignment to a BDE.

9–10. BDE works the lead + live comms

Log in as the BDE, open the Lead Cockpit, qualify the lead and schedule a site visit — your phone receives the real WhatsApp confirmation. Show the activity timeline filling with sent messages and automations.

11. Pre-sales → sales → post-sales

Move the lead through the stages on the pipeline. Some stages ask for a couple of fields (budget, timeline) — pre-fill them so nothing blocks you on stage.

12. Booking, cost sheet & payments
  1. Mark the deal Won → a booking is created and the unit is held/booked.
  2. Generate the cost sheet, pick a payment plan, and record a payment — a serial receipt is produced.
  3. To show a payment/visit reminder instantly (instead of waiting), an admin can SSH in and run:
    php artisan crm:reminders (and php artisan crm:email-scheduled, php artisan wa:campaigns:dispatch).
